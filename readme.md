# wt901

Automatic data collection from a [WitMotion WT901SDCL-BT50](https://www.wit-motion.com/) IMU.

The sensor records to its own SD card while worn. When it is docked over
USB-C it mounts as a mass-storage volume — this script notices that,
copies the recordings, decodes the binary format into JSON Lines, frees
space on the card and unmounts the volume. It can also configure the
sensor over Bluetooth LE.

Built for capturing hand motion during dairy work, but nothing in it is
specific to that.

## Requirements

- Python 3.8+ (collection uses only the standard library)
- `bleak` — only for the Bluetooth configuration commands
- macOS or Linux

```bash
pip install bleak
```

## Quick start

```bash
# 1. See what the sensor exposes
python3 wt901.py --list

# 2. Watch a dock cycle happen
python3 wt901.py --monitor

# 3. Once you trust it, install the background agent
python3 wt901.py --install --delete
```

After step 3 there is nothing left to run. Dock the sensor, wait for the
volume icon to disappear, take it back.

## Collection

| Command | Effect |
|---|---|
| `--monitor` | live terminal view of the next dock cycle |
| `--once` | single pass, then exit |
| `--list` | show volumes and the files on them |
| `--delete` | clear the card after a verified copy |
| `--install` | run automatically on connect (launchd / udev) |
| `--uninstall` | remove the agent |
| `--volume NAME` | only touch volumes matching this name |
| `--keep-raw` | keep the binary `.TXT` after decoding |

## Configuration over BLE

| Command | Effect |
|---|---|
| `--scan` | find the sensor |
| `--verify` | read back current settings |
| `--listen` | live data stream, measures the real sample rate |
| `--apply` | set output rate and filter bandwidth |
| `--rate 50` | choose 20, 50, 100 or 200 Hz |
| `--settime` | sync the sensor clock to this computer |

The sensor's real-time clock drifts badly — check it with `--listen` and
re-sync when needed. Timestamps are the only thing tying recordings to
reality, so this is worth watching.

## Output layout

```
~/Projects/wt901-data/
├── collector.log
├── collected.json
└── COW01/                          # one folder per sensor, from the volume label
    └── sessions/
        └── 20260823_200412/        # dock time
            ├── session_20260823T080000.jsonl
            └── SET.TXT             # sensor config at the time of recording
```

Each line of a `.jsonl` file is one sample:

```json
{"t":"2026-08-23T08:00:00.000","ax":0.293,"ay":-0.146,"az":1.025,
 "gx":305.2,"gy":-122.1,"gz":183.1,"roll":0.549,"pitch":1.099,"yaw":1.648}
```

Acceleration in g, angular velocity in deg/s, angles in degrees.

## Multiple sensors

Every card ships labelled `NO NAME`, which collides with any unlabelled
USB stick. Give each one a real label before deploying:

```bash
diskutil rename "/Volumes/NO NAME" COW01
```

The label becomes the folder name and is part of the deduplication key,
so two sensors with identically named files will not overwrite each other.

## Notes on the hardware

- The sensor starts a new file every 12 MB. A continuous recording is
  therefore split across several `WIT*.TXT` files; the decoder merges them
  back into real sessions using timestamps.
- Recording continues while the sensor is docked, so the newest file on
  the card is never deleted.
- `SET.TXT` is generated by the sensor and ignored when edited by hand.
  Use `--apply` and `--settime` instead.
- At 100 Hz with accel + gyro + angles the sensor produces about
  2.7 KB/s — roughly 80 MB per eight-hour shift.

## Safety

- Files are read once, hashed inline, and the copy is verified before
  anything is deleted.
- Without `--delete` nothing is ever removed from the card.
- An unreadable file is retried, then skipped; the rest still copy.
- Already-collected files are remembered, so repeated runs are harmless.
